# Updating the GEMMA Lab website

The site is built with [Quarto](https://quarto.org). You write plain text files
(`.qmd`), push them to GitHub, and GitHub renders and publishes the site for you.

**You do not need R, Quarto, or anything else installed to make a normal update.**
Editing a file in the GitHub web interface is enough. The site rebuilds itself
within a couple of minutes.

---

## The 30-second version

| I want to… | Edit this file |
|---|---|
| Add or remove a lab member | `people.qmd` |
| Add a paper | `publications.bib` |
| Add a news item | `news.qmd` |
| Add a talk | `talks.qmd` |
| Add or change a home-page genome story | `_data/stories.yml` |
| Change the home page | `index.qmd` |
| Change a research description | `research.qmd` |
| Add a photo to the gallery | `photos.qmd` (+ drop the image in `images/`) |
| Add a collaborator | `collaborators.qmd` |
| Change colours or fonts | `theme/gemma.scss` |
| Change the menu bar | `_quarto.yml` |

## Editing from the browser (no software needed)

1. Go to the file on GitHub.
2. Click the pencil icon (**Edit this file**).
3. Make your change.
4. Scroll down, write a short note like "add Zehta's new paper", click
   **Commit changes**.
5. Go to the **Actions** tab. A job called *Render and publish site* starts
   automatically. When it turns green, the change is live at
   <https://www.gemmalab.org>.

If the job turns red, the page did not publish — click into it to see the error.
The previous version of the site stays online until a build succeeds, so a
mistake can never take the site down.

## Adding a paper

Open `publications.bib` and paste a new entry **at the top**. From Google
Scholar you can click the quote icon → *BibTeX* and paste it in, then tidy it to
match this shape:

```bibtex
@article{lastname2026keyword,
  number  = {41},
  title   = {The full title of the paper},
  author  = {Jane Doe and Fausto Rodríguez-Zapata and Rubén Rellán-Álvarez},
  year    = {2026},
  journal = {New Phytologist},
  url     = {https://doi.org/10.1234/whatever},
  pdf     = {pdfs/41-2026-doe.pdf},
  code    = {https://github.com/rr-lab/some-repo},
  codelabel = {Code},
  note    = {PREPRINT},
  summary = {One or two sentences on what we actually did.}
}
```

- `number`, `title`, `author`, `year` are required. Everything else is optional —
  just delete the lines you don't need.
- Authors are separated by ` and `, not commas.
- **Do not bold lab members by hand.** Names listed in `_lab_authors.txt` are
  bolded automatically, and matching ignores accents and hyphens, so
  `Rellan-Alvarez` in that file matches *Rubén Rellán-Álvarez*,
  *Ruben Rellan-Alvarez* and *Rellán- Álvarez R* alike. When someone new joins the
  lab, add their surname to `_lab_authors.txt` once and every paper updates.
- `journal` is shown next to the paper in the home page's *New this year* list.
- `codelabel` is the text on the `code` link (default *Code*), e.g. `{SoLD Shiny app}`.
- `summary` becomes the collapsible **What we did** panel under the paper.
- Species names use markdown italics: `*mexicana*`.
- Papers are grouped and sorted automatically by `year` and `number`. You never
  touch the page layout.
- For a PDF, upload the file into the `pdfs/` folder and point `pdf` at it.

`publications.qmd` itself only holds the intro text — the list is generated by
`scripts/build_publications.py` every time the site builds.

## Adding a lab member

Open `people.qmd` and copy an existing block. Each person is:

```
::: {.person}
[Full Name]{.person-name}
[Their role]{.person-role}

::: {.person-bio}
One or two sentences about what they work on.
:::

::: {.person-links}
[<i class="bi bi-github"></i>](https://github.com/username "GitHub")
[<i class="bi bi-envelope"></i>](mailto:name@ncsu.edu "Email")
:::
:::
```

- The `.person-links` block is optional — delete it if there's nothing to link.
- Icon names come from [Bootstrap Icons](https://icons.getbootstrap.com); useful
  ones are `bi-github`, `bi-envelope`, `bi-file-text`, `bi-mortarboard`
  (Google Scholar), `bi-globe`, `bi-linkedin`.
- **To add a headshot**, put the image in `images/` and add this line as the
  first thing inside the `::: {.person}` block:
  `![](images/their-photo.jpg){.person-photo}`. It gets cropped to a circle
  automatically. Best results with a roughly square photo.
- When someone leaves, move their name into the `## Former lab members` list at
  the bottom of the page — and remember to leave their surname in
  `_lab_authors.txt` so their papers stay bolded.

## Adding a news item

Open `news.qmd`. Add a bullet at the **top** of the current year's list:

```
## 2026

::: {.timeline}
- Your newest item goes here, with [links](https://example.com) if you like.
- The item that used to be newest.
:::
```

For a new year, copy the `## 2026` heading and the `::: {.timeline}` / `:::`
wrapper. To include a picture with an item, indent it underneath:

```
- We had a great harvest this year!

  ![](images/harvest2026.jpg)
```

## Adding a photo to the gallery

1. Put the image file in the `images/` folder.
2. Open `photos.qmd` and add a line inside the `<div class="gallery">` block:

```html
<a href="images/newphoto.jpg"><img src="images/newphoto.jpg" alt="Short description" loading="lazy"></a>
```

Add `class="g-wide"`, `class="g-tall"` or `class="g-big"` to make a photo take up
more space in the grid. Always write a short `alt` description — it's what screen
readers announce.

If a filename contains spaces or brackets, replace each space with `%20` in the
`href` and `src` (or, easier, rename the file).

## Adding a story to the home page

The "Stories in the genome" panel on the home page is drawn from
`_data/stories.yml`. Each story is one entry; copy an existing one and edit it.

- `loci` lists positions in Mb on B73 v5 (`chr`, `start_mb`, `end_mb`, and an
  optional `gene`). Leave it as `loci: []` and the story shows "Not yet mapped".
- Set `coords_verified: true` once the positions are checked against
  [MaizeGDB](https://www.maizegdb.org). Until then the panel says "approximate
  position".
- `inversion: true` adds the "Standard / Inverted in highland maize" bar.
- Text fields take markdown, so `*HPC1*` comes out in italics.
- A gene in `genes` can be plain text or `{name: "*HPC1*", id: Zm00001eb121780}`.
  With an `id`, the gene links to its MaizeGDB page. B73 v5 positions for an
  id can be looked up at
  `https://rest.ensembl.org/lookup/id/<id>?content-type=application/json`.
- Only list genes that are published or preprinted.

A story can be linked to directly: `https://www.gemmalab.org/#story-hpc1`.

The home page's publication chart, *New this year* list and latest news are
built automatically from `publications.bib` and the top of `news.qmd`.

## Changing the look

All colours, fonts and spacing live in `theme/gemma.scss`. The palette is at the
very top of the file; change one of these and the whole site follows:

```scss
$paper:   #FFFFFF;  // page background
$ink:     #1B2430;  // body text, headings
$muted:   #4A5866;  // labels, captions, metadata
$panel:   #F3F5F7;  // tinted panels
$rule:    #D3DAE1;  // hairlines
$accent:  #1F5FA6;  // links, buttons, bars
```

The fonts (IBM Plex Sans and IBM Plex Sans Condensed) are loaded in
`theme/head.html`. Keep text at 4.5:1 contrast or better against its background.

The menu bar, footer and site title are in `_quarto.yml`.

## Working locally (optional)

If you'd rather preview changes before pushing:

```bash
# once
brew install --cask quarto     # or download from quarto.org

# then, from the repo folder
quarto preview
```

This opens the site in your browser and reloads as you save. `quarto render`
builds it into `_site/` without opening a browser.

You need Python 3 available for the publications script — macOS already has it.

## How it fits together

```
_quarto.yml                  site config: menu, footer, theme
theme/gemma.scss             all colours, fonts and component styles
theme/head.html              font loading
theme/genome.js              draws the home page's genome panel
theme/stories.lua            passes _data/stories.yml to genome.js
_data/stories.yml            the home page's genome stories
*.qmd                        one file per page
publications.bib             the papers
_lab_authors.txt             surnames to bold automatically
scripts/build_publications.py  turns the .bib into the formatted list and
                             builds the home page's chart and lists
.github/workflows/publish.yml  renders and publishes on every push
_generated/                  script output — not committed
_site/                       the built website — not committed
_legacy/                     the old R Markdown site, kept for reference
```

`_generated/` and `_site/` are rebuilt from scratch every time, so there is never
any reason to edit or commit them.

## One-time setup checklist

If the site hasn't published yet, check these in the GitHub repo:

1. **Settings → Pages → Build and deployment → Source** must be set to
   **GitHub Actions** (not "Deploy from a branch").
2. **Settings → Pages → Custom domain** should read `www.gemmalab.org`.
   The `CNAME` file in this repo keeps that setting in sync.
3. **Settings → Actions → General → Workflow permissions** — the workflow needs
   permission to write to Pages; the defaults are usually fine.

Once the first green build finishes, `_legacy/` can be deleted whenever you're
happy with the new site.
